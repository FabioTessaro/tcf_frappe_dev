# 13 · Request lifecycle

## Purpose

The path of one user action through the system, naming the component responsible at each step.
Use it to decide where a piece of logic belongs.

## Portal request

```
View ─► composable ─► feature api module ─► shared/frappe client ──HTTP──►
  portal page / router guard (UX only)        adds CSRF, X-Trace-Id, handles error envelope

──► Frappe request ─► request guard (core) ─► whitelisted method in <feature>/api.py
                                               decorated with sdk portal_api():
                                                 auth · role gate · rate tier · pydantic validation
──► service.py (commands) / queries.py (reads) ─► doctype controllers (single-doc invariants)
──► audit capture (same transaction) ─► response shaped by schemas.py
      errors → error envelope (code, params, message, fields, trace_id)
──► client maps envelope → UI (translated by error code) ; realtime events follow asynchronously
```

## Rules

- `SYS-LIFE-001` Every portal request MUST carry an `X-Trace-Id` header generated by the client
  per user action; the backend MUST create one if missing and propagate it to logs, jobs,
  realtime payloads and error envelopes
  ([30-security-and-compliance/306-observability](../30-security-and-compliance/306-observability.md)).
- `SYS-LIFE-002` Each step MUST stay within its responsibility as stated in
  [10-frontend/101-structure](../10-frontend/101-structure.md) and
  [20-backend/201-layers](../20-backend/201-layers.md). Business rules MUST NOT live in views,
  API modules or whitelisted functions.
- `SYS-LIFE-003` Every response from a whitelisted method that fails MUST use the error envelope
  ([03-contracts/30-error-catalog](../03-contracts/30-error-catalog.md)).
- `SYS-LIFE-004` Every response MUST carry the `X-Build-Id` header
  ([03-contracts/32-boot-data](../03-contracts/32-boot-data.md)).

## Background work

`service.py` enqueues jobs through the sdk wrapper (which propagates `trace_id`); jobs call
services; progress and results reach the user via realtime events scoped to the user or document.
