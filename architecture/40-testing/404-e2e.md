# 404 · End-to-end tests

## Structure (`<core-app>/frontend/tests/e2e/`)

- `global-setup.ts`: prepares the test site — seeds, users per role and per party type, stored
  logged-in sessions.
- `fixtures/`: logged-in-as-role and logged-in-as-party-member fixtures; seeded data handles.
- `pages/`: page objects (login, launcher, app shell) so specs describe behaviour, not selectors.
- `specs/`: journeys, each run on a desktop and a mobile viewport.

Feature apps add specs in `<feature-app>/frontend/tests/e2e/specs/`; core's Playwright config
discovers and runs them.

## Mandatory journeys (core)

- Guest opens the launcher, is sent to login, returns after login.
- Launcher shows exactly the apps allowed for each role and party type.
- Opening an app, navigating its sidebar, returning to the launcher.
- Direct URL to an app the user cannot access.
- Session expiry during use sends the user to login.
- Connection lost mid-session shows the banner, which clears on reconnect.
- After a deploy, a tab hitting a missing chunk reloads once and recovers; build-id mismatch shows
  the reload prompt.
- An external user sees only their party's records and cannot reach Frappe's generic API.
- Public website: the portal button leads guests to login and logged-in users to the launcher.
- File upload with `antivirus: required` is unavailable until scanned clean.

## Rules

- `TST-E2E-001` E2E runs against the built image on a disposable stack (compose) with the test
  site, never against a shared or production site.
- `TST-E2E-002` Every feature app MUST add specs for its main journeys.
