# 503 · Continuous delivery

## Target

A VPS running Docker Compose. Production and staging are separate compose projects (staging on its
own host when resources allow).

## Image

One immutable image per platform release (bench, Frappe and all apps at the locked versions,
built frontend), built only in CI from the `platform` repository.

## Deploy procedure (`just deploy env=…`)

1. Manual approval (GitHub environment `staging` / `production` with required reviewers).
2. Verify the image signature (cosign).
3. Encrypted backup of the database and a snapshot of the object store
   ([60-operations/601-backup-and-restore](../60-operations/601-backup-and-restore.md)).
4. Pull the image from the GitHub Container Registry on the target host.
5. Run `bench migrate` in a one-off container from the new image.
6. Replace web, workers, scheduler and socket.io containers.
7. Smoke test: health checks plus login and one journey per app.
8. Record an Audit Event "deployed `<version>` by `<user>`".

## Rules

- `DEL-CD-001` Images MUST NOT be built on servers; servers only pull signed images from the
  registry.
- `DEL-CD-002` Every release MUST be deployed to staging and pass the smoke test before production.
- `DEL-CD-003` Steps 2, 3 and 8 are mandatory and MUST NOT be skipped, including for hotfixes.
- `DEL-CD-004` Rollback = previous image + restore of the pre-deploy backup (patches are not
  reversible). The rollback procedure MUST be tested at least quarterly on staging.
- `DEL-CD-005` Secrets are provided to containers from the host's encrypted environment files, never
  baked into images.
- `DEL-CD-006` Staging doubles as the integration sandbox; it MUST contain only synthetic data.
